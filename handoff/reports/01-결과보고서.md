# Orcinus 결과 보고서 — SFTP 파일 관리 기능

**작성일**: 2026-08-28 · **대상**: Orcinus(Orca 기반 커스텀 ADE) · **범위**: SFTP 파일 관리 기능 개발 및 릴리스

## 1. 개요

Orcinus는 오픈소스 IDE/ADE **Orca**(`stablyai/orca`)를 개인 계정으로 포크한 커스텀 데스크톱 애플리케이션이다. 본 프로젝트는 세 단계로 진행됐다.

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 포크·리브랜딩 (이름/아이콘/식별자 → Orcinus) | 완료 (2026-08-20) |
| 2 | New Window (두 번째 앱 창 + 창별 터미널·세션 라우팅) | 완료 (2026-08-24) |
| 3 | **SFTP 원격 파일 관리** | 완료 (2026-08-28) |

본 보고서는 3단계(SFTP)를 중심으로, 형상관리·개발 스택·미결 항목을 정리한다.

## 3. SFTP 기능 (3단계 산출물)

릴레이 서버 없이 `ssh2` 라이브러리로 원격 호스트에 직접 접속하는 구조로 구현했다. 모든 원격 작업은 예외를 던지지 않고 `{ error }` 형태를 반환하는 IPC 계약을 따른다.

### 3.1 원격 파일 브라우징·조작
- 우측 사이드바 **Server Explorer**: 저장된 SFTP 호스트 선택 → 원격 디렉토리 트리 탐색.
- 파일 메타데이터 표시: 크기, 최종 수정 시각, POSIX 권한(rwx).
- 업로드: 파일/디렉토리, 이름 충돌 시 사용자 프롬프트(덮어쓰기 / 이름 직접 입력 / 건너뛰기), 완료 후 자동 새로고침.
- 다운로드: 단일 파일, 그리고 **다중 선택 → 단일 `.tar.gz` 아카이브**(원격 `tar`를 exec 채널로 스트리밍).
- 이동(드래그·드롭, 비원자적 덮어쓰기를 백업-후-교체로 원자화), 삭제(확인 다이얼로그), 새 디렉토리 생성.

### 3.2 원격 파일 열람 — 네이티브 에디터 통합
- 초기: 독립 팝업 뷰어(`@monaco-editor/react`, read-only, 10MB 캡).
- 개선: 로컬 파일과 **동일한 메인 워크스페이스 에디터**에서 read-only 탭으로 열람하도록 전환.
  - `OpenFile.sftpTargetId` 필드 + 콘텐츠 로더의 SFTP 분기로, 워크트리/SSH/런타임 라우팅을 우회해 원격 내용을 읽는다.
  - 활성 워크트리를 탭 소유자로 사용(기존 "View Log" 읽기전용 탭 선례 재사용).
  - 에디터 파일 식별자를 호스트로 네임스페이스(`sftp:`)해, 같은 절대경로의 로컬/SSH 탭과 충돌 방지.
  - 원격 마크다운 파일의 프리뷰 렌더 지원.
- 원격 파일 탭은 왼쪽 아이콘을 서버 글리프로 표시해 시각적으로 구분.
- 상호작용: 단일 클릭 = 선택만, 더블 클릭 / 우클릭 메뉴 = 열람.

### 3.3 분할 패널 + 양방향 드래그 전송
- 로컬 파일 탐색기 하단에 Server Explorer를 분할 배치(드래그 구분선, 상태 localStorage 지속).
- **업로드 드롭**: 로컬 항목을 SFTP 패널에 드롭 → 다이얼로그 없는 업로드.
- **다운로드 드롭**: 원격 항목을 로컬 패널에 드롭 → 다이얼로그 없는 다운로드(파일=temp+rename, 디렉토리=재귀 walk).
- 로컬/원격 드래그를 구분하기 위한 별도 MIME(`text/x-orca-sftp-file`, `{hostId, paths}`) 도입. 로컬 이동/undo·네이티브 OS 파일 드롭은 무손상.

## 4. 품질·보안

각 기능은 게이트(타입체크·린트·단위 테스트·현지화) 통과 후, 다차원 적대적 코드 리뷰를 거쳐 커밋했다. 리뷰가 발견해 교정한 주요 결함:

| 심각도 | 결함 | 교정 |
|---|---|---|
| High | 아카이브 `tar` 명령에 대시(-)로 시작하는 원격 파일명이 옵션으로 해석(예: `--checkpoint-action=exec=…` → RCE) | `--` 종결자 추가 |
| High | 다운로드가 기존 로컬 파일을 무경고 덮어쓰기 | 네이티브 드롭 관습(`name copy`)으로 비파괴 처리 |
| Medium | 원격 심볼릭 링크를 따라가 링크 대상 유출(업로드·다운로드) | 최상위 심링크 거부 / 권한 비트 확정 분류로 스킵 |
| Medium | 원격 파일 탭이 같은 경로의 로컬/SSH 편집 탭과 식별자 충돌 | 호스트 네임스페이스 id + 재사용 가드 |
| Medium | 신호로 종료된 `tar`를 성공으로 오인해 잘린 아카이브 저장 | 시그널 종료를 실패 처리 |

원격 경로는 모두 셸 이스케이프하며, 로컬 대상 파일명은 메인 프로세스에서 sanitize해 경로 이탈을 차단한다.

## 5. 개발 스택

- **런타임/프레임워크**: Electron 43, TypeScript, React, Zustand(상태), Radix/shadcn UI, sonner(토스트), lucide-react(아이콘), @monaco-editor/react.
- **원격**: `ssh2`(SFTP/exec), 릴레이 없는 커넥션 풀.
- **빌드**: electron-vite(번들) + electron-builder(패키징, NSIS 원클릭 설치기), 네이티브 모듈(node-pty·ssh2) win32-x64 리빌드·서명.
- **테스트/게이트**: vitest, oxlint, 타입체크(node·web 병렬), 현지화 카탈로그 동기화.
- **대상 OS**: Windows(주), macOS/Linux 호환 고려.

## 8. 미결 항목

- **upstream 재동기화(연기)**: `upstream/main`(현재 201커밋 뒤)을 병합하려면, 기계적 충돌(확정된 recipe)과 PTY 게이트 재직조(확정)는 해결되나, **멀티윈도우 PTY 스트림 전달 서브시스템(약 1,500줄)을 upstream의 분할 구조 위에 재구현**하는 별도 기능 작업이 남는다. 두 차례 시도로 경계를 확정하고 인수인계 문서(`03-upstream-동기화-인수인계.md`)에 정리했다.
- 셸/WSL 관련 일부 테스트는 Windows 경로 구분자 등 환경 의존 이슈로, 본 기능과 무관하다.
